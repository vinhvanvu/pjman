# Work trackers and PM tools moving into AI-agent coordination, ownership and decision-making (as of 2026-10-09)

Scope note for the writer: every claim below is dated and tagged **shipped** / **announced** / **beta** where the source allows. Primary sources (vendor changelogs, press releases, official blogs) were fetched directly where possible; secondary sources (trade press, aggregators) are marked as such. "Absence" findings are explicit: where a vendor does not do something pjman proposes, that is stated. Research was conducted 2026-10-09 using web search plus direct fetches of vendor pages.

## Key question 1 — Linear: Agent API / "agents as teammates", Linear's own coding agent, decisions / ownership / approvals, founder direction

### Takeaway
Linear is the tracker that has moved furthest and fastest: agents became first-class workspace members in May 2025, Linear shipped its own agent (March 2026), its own code review surface (Diffs, May 2026) and its own coding agent via Claude Code/Codex (June 2026), and its CEO publicly reframed the company as "context infrastructure" with the slogan "issue tracking is dead" and "context becomes the product". But as of 2026-10-09 Linear ships **no decision object, no ownership model beyond assignee/lead, no derived approvers, no maturity model and no declared-vs-observed drift** — its "human remains primary assignee" rule is the only accountability primitive.

### Cited Findings

Assign them to issues, add them to teams and projects, and @mention them in comments – just like any other member of your workspace." Launch agents: Devin (scopes issues, drafts PRs), ChatPRD (writes requirements, manages issues), Codegen (builds features, debugs, answers codebase questions). Custom agents can be built for private workspace use or submitted to the Integration Directory via the new Agent API. No pricing stated in the entry. — [Linear changelog 2025-05-20](https://linear.app/changelog/2025-05-20-linear-for-agents)

**Founder direction (2025–2026)**
- **2026-03-26, Karri Saarinen:** declared "issue tracking is dead"; positioned Linear as context infrastructure for coding agents rather than a workflow tool; issues nonetheless remain Linear's core unit. — [The Register, 2026-03-26](https://www.theregister.com/2026/03/26/linear_agent/); [TBPN digest, 2026-03-26](https://www.tbpndigest.com/story/2026-03-26/linear-ceo-karri-saarinen-declares-issue-tracking-is-dead-and-reveals-linears-ai-era-pivot)
- **Saarinen open letter (March 2026) quotes:** "Agents are not mind readers – they become useful through context." / "Customer feedback, internal ideas, strategic direction, **decisions**, and code all need to be captured in a system that humans and agents can work from together." / "The best systems remove overhead so teams can focus on building." The described vision: systems that interpret intent, route work, escalate when necessary. — [Tessl, "Issue tracking is dead"](https://tessl.io/blog/issue-tracking-is-dead-linear-ceo-explains-why-the-company-is-betting-on-agents)
- **Lenny's Podcast, 2026-09-29 (Saarinen):** "Don't become a software factory where you outsource all the work and thinking to somewhere else." / "More output isn't better. Customers are not buying the lines of code." / "Context becomes the product." / "Eventually if you don't learn from the work you do … you would lose the advantage." Argues automating execution without preserving the learning loop severs the feedback mechanism; organisations should shift toward context management. — [BigGo Finance summary of Lenny's Podcast](https://finance.biggo.com/news/936aa818c5c732f4) (secondary summary; original is the podcast)
- Saarinen also did a Sequoia fireside (Stephanie Zhan) on "what genuinely changes when agents become part of the team" and discussed Linear's initial hesitancy about generative AI and the tipping point. — [Linear press page](https://linear.app/now/press); [Runtime interview](https://www.runtime.news/linear-ceo-karri-saarinen-our-customer-base-is-quite-powerful/)

**Absences (checked against the full 2026 changelog index and the agents page)**
- No "decision" record type, no decision log, no rationale field as a queryable object (the word "decisions" appears only in Saarinen's letter). — [Linear changelog index](https://linear.app/changelog)
- No ownership model beyond assignee / project lead / "team initiatives" (2026-08-13: "assign a team to lead an initiative"). — [Linear changelog index](https://linear.app/changelog)
- No approval workflow on issues or projects; the only approvals are admin approvals of third-party apps. — [Linear changelog index](https://linear.app/changelog)
- No maturity / readiness model and no declared-vs-observed drift detection; Code Intelligence reads code to answer questions and design specs, it does not diff declared intent against code. — [Linear changelog 2026-03-24](https://linear.app/changelog/2026-03-24-introducing-linear-agent)

### Inferences
- Linear's trajectory is *downward* into execution (own coding agent, own review UI, sandbox runtime pricing, model routing) rather than *upward* into alignment (decisions, authority, approvals). The one explicit accountability rule — human stays primary assignee — is a ticket-level assignment convention, not an ownership graph.
- Saarinen's rhetoric ("context becomes the product", decisions must be captured) is directionally identical to pjman's thesis, which means Linear is the most plausible "build it from above" competitor; but nine months after the letter, the shipped surface is still issue-centric. The Register notes issues remain the core unit even after the "dead" declaration.
- Pricing direction (usage-based credits for automation/coding, spend limits) suggests Linear's monetisation is converging on agent compute, not on signers/approvers.

### Gaps
- Could not fetch Saarinen's March 2026 open letter directly (only quoted via Tessl); exact title/URL of the letter not confirmed.
- No primary source found for agent-seat pricing policy (only aggregator pages); Linear's own pricing page was not fetched.
- Exact GA date and final pricing of Code Intelligence not found (announced "coming soon" 2026-03-24; coding sessions shipped 2026-06-11 — unclear whether "Code Intelligence" shipped under that name).

## Key question 2 — Atlassian: Rovo agents, Jira agent features, Teamwork Graph (decisions? ownership?), Compass status

### Takeaway
Atlassian has the most explicit *graph* story: at Team '26 (2026-05-06) it opened the Teamwork Graph (150B+ connections; CLI with ~300 commands; Rovo MCP server), made "Agents in Jira" GA with audit trails, and its marketing says the graph captures "why a decision was made, who owns it now". However, the developer glossary defines only generic object types (work item, document, project, user) and relationship classes (canonical / activity / inferred) — **no decision entity, no approval entity, no maturity, no drift** is documented in the public data model. Compass (service catalog) appears to be being folded into DX with sales ending 2026-05-13 (secondary source only).

### Cited Findings

**Team '26 (2026-05-06) announcements**
- Teamwork Graph "spans more than 150 billion connections"; opened via two interfaces in open beta: a **Teamwork Graph CLI** (programmatic access from local tooling and CI; ~300 commands, usable by Claude Code and Cursor) and **Teamwork Graph tools in Rovo's MCP server** (third-party agents read/write graph context). Claimed effect: "44% more accurate results while using 48% fewer tokens" when grounding AI in graph data. Connectors GA on Forge. — [SiliconANGLE, 2026-05-06](https://siliconangle.com/2026/05/06/atlassian-opens-teamwork-graph-pushes-rovo-agentic-execution-team-26/)
- Rovo usage: 14M Rovo-assisted actions in the prior month; agentic automations up 7× over six months; 90%+ of enterprise cloud customers using Rovo. **Rovo Studio GA** — no-code agent/automation builder with "built-in roles, approvals, versioning and audit controls" (approvals here govern the *agents*, not work changes). **Max Mode** (early access soon): multistep plans with user review loops. **Jira Agents GA** with full audit logging. **Jira Product Discovery Enterprise GA** with portfolio governance and a new Feedback capability. Admin: org-wide agent inventory, separated permissions for AI access vs agent building, audit logs for credit consumption, data residency, LLM selection policies. — [SiliconANGLE, 2026-05-06](https://siliconangle.com/2026/05/06/atlassian-opens-teamwork-graph-pushes-rovo-agentic-execution-team-26/)
- Atlassian's own blog on the graph: it represents people (owners, contributors, collaborators), goals, code (Bitbucket), **decisions ("why a decision was made, who owns it now")**, work items, Confluence/Loom content, projects, dependencies; "over 150 billion objects and relationships" as of May 2026; CLI GA with OAuth, audit logs, granular scopes; Rovo MCP server open beta; "Data enters the graph with its access controls intact, so AI respects who can see what." The post contains **no statements** on human accountability, approval workflows, or declared-vs-actual drift. — [Atlassian blog, Teamwork Graph at Team '26](https://www.atlassian.com/blog/company-news/teamwork-graph-team-26)
- Developer glossary: object types listed are Jira work item, User, Atlassian project (API) and Work item, Document, Project (connectors). Relationship classes: **canonical** ("direct, structural connection … ownership, containment, and logical associations, such as a work item belonging to a project"), **activity** (user actions), **inferred** (derived by the graph via pattern analysis/ML). **The glossary defines no Decision, Owner, Approval, Goal or Component type.** — [Atlassian developer glossary, Teamwork Graph](https://developer.atlassian.com/platform/teamwork-graph/glossary/)
- Secondary analyses of the graph say users can run lookups such as "Who are the owners of this decision?" and that decisions are captured as knowledge entities (i.e., Confluence content), and that the graph shows "who owns specific tasks, services, or initiatives". — [Adaptavist, Teamwork Graph explainer](https://www.adaptavist.com/blog/atlassian-teamwork-graph); [Port, Teamwork Graph vs Context Lake](https://www.port.io/blog/teamwork-graph-vs-port)

**Agents in Jira (GA May 2026)**
- "Agents in Jira is now generally available for all Jira Cloud Standard, Premium, and Enterprise plans"; agents "take ownership of tasks, such as assigning issues or updating the code in a Jira bug"; triggered when assigned, @mentioned, or when work moves into a designated status; "every agent action is logged in Jira with a full audit trail, and admins control which agents run and where". — [Atlassian Community, "Introducing Agents in Jira"](https://community.atlassian.com/forums/Jira-articles/Introducing-Agents-in-Jira/bc-p/3253422); [Futurum, "Atlassian Fuses the Agent Work Surface, Workflow, and Control Plane Into Jira"](https://futurumgroup.com/insights/atlassian-fuses-the-agent-work-surface-workflow-and-control-plane-into-jira/)
- **Agent Accounts:** an agent can act as itself with its own permissions rather than the automation owner's; per-agent choice between invoking-user permissions and its own account. — [secondary: Atlassian Community Team '26 Rovo overview](https://community.atlassian.com/forums/Atlassian-AI-Rovo-articles/The-ultimate-TEAM-26-Rovo-announcement-overview-and-more/ba-p/3241987)
- **Code Context (announced):** "brings large-scale, multi-repo codebase understanding into the Teamwork Graph, so Rovo and AI coding agents can reason across connected source code and the work around it." — [Jira releases announcement](https://jirareleases.atlassian.com/announcements/bring-code-context-to-rovo-and-ai-coding-agents)
- **2026-10-06 — OpenAI partnership expanded:** GPT-6 family (incl. "GPT-6 Astra" and the GPT-5.6 series) to power agents across Atlassian's platform and Rovo; OpenAI supplies reasoning, Teamwork Graph supplies organisational context; builds on a 2023 collaboration. — [Channel Insider, 2026-10-06](https://www.channelinsider.com/channel-business/news-openai-atlassian-partnership-gpt-6-rovo/); [OpenAI partnership page](https://openai.com/index/atlassian-partnership/)
- Forbes (2026-10-09) frames Atlassian's strategy as a "move to own the context powering enterprise agentic AI". — [Forbes, 2026-10-09](https://www.forbes.com/sites/stevemcdowell/2026/10/09/atlassians-move-to-own-the-context-powering-enterprise-agentic-ai/)
- Rovo Dev (coding agent) was made generally available (DevOps.com). — [DevOps.com](https://devops.com/atlassian-makes-ai-coding-agent-generally-available/)

**Compass**
- At Team '25 Europe Atlassian bundled Rovo Dev, Bitbucket, Compass and DX (engineering metrics) into an "Atlassian Software Collection". — [Adaptavist, Team '25 Europe](https://www.adaptavist.com/blog/atlassian-team-25-europe-latest-announcements)
- Secondary report: on 2026-04-17 Atlassian announced Compass scorecards and catalog functionality will move into DX, with sale of Compass ending 2026-05-13. — [search-result snippet attributed to Atlassian/Compass changelog](https://developer.atlassian.com/cloud/compass/changelog/) — **not verified against a primary page; treat as needing confirmation.**
- Rovo MCP server lists Compass among the products it can reach (Jira, Confluence, Compass, JSM). — [Atlassian Rovo MCP supported tools](https://support.atlassian.com/ja/atlassian-rovo-mcp-server/docs/supported-tools)

**Absences**
- No derived-approver mechanism for Jira issues was found; Jira Service Management has long had approval steps, but nothing was found that derives approvers from what a change touches in code or product structure.
- No maturity/readiness model as claim-plus-evidence was found (Compass scorecards were observed-check rubrics on services, and are reportedly moving into DX).
- No declared-vs-observed drift detection was found; Code Context is described as understanding code for reasoning, not diffing declared state.
- No open file-based format: the graph is accessed via CLI/MCP/API only.

### Inferences
- Atlassian's "decisions" are Confluence pages/knowledge content connected into the graph, not a typed decision record with a required owner and rationale schema. The marketing ("why a decision was made, who owns it now") outruns the documented data model.
- Rovo Studio's "approvals" and Jira's audit trails govern *agents as actors* (who may run what, with what permissions). This is control-plane governance, not change governance; the approver of a change is still whoever the Jira workflow is configured to require.
- Atlassian is the vendor most likely to add a typed decision/ownership layer because it already owns Confluence decisions, Jira ownership fields, Goals/Focus, and the graph; the opening of the graph via CLI/MCP also means pjman could *read* it as a source rather than compete head-on.

### Gaps
- Could not confirm the Compass→DX transition from a primary Atlassian page.
- Pricing for Rovo credits, Teamwork Graph CLI, and Agents in Jira was not disclosed in any fetched source (SiliconANGLE explicitly notes no pricing was given).
- Did not find an Atlassian executive quote on human accountability or approvals specifically.

## Key question 3 — GitHub: Copilot coding agent, Agent HQ, Projects, Spec Kit, issue→agent→PR flows, CODEOWNERS, decision records

### Takeaway
GitHub owns the canonical issue→agent→PR loop (coding agent, 2025-05-19; Agent HQ "mission control" with third-party agents, 2025-10-28) and governs it with its existing primitives: branch protection, required reviews, "requester cannot approve their own agent PRs", Actions runs gated on human approval. **CODEOWNERS is the only shipped instance in any vendor of "approvers derived from what a change touches"**, and it has not evolved for agents. Spec Kit (open source, markdown-in-repo, 38 agents) is the only open, file-based, local-first artifact chain, but it has no owners, approvals or decision records. GitHub Projects has no agent-specific features found.

### Cited Findings
- **2025-05-19 — Copilot coding agent (shipped, Enterprise + Pro+):** assign an issue to Copilot on github.com, Mobile, CLI or VS Code; it boots a VM, clones, analyses the codebase, pushes commits to a draft PR with session logs; tags the developer for review; addresses review comments. Constraints: pushes only to branches it creates; "required reviews" honoured; **requester cannot approve their own agent PRs**; restricted internet allowlist; "GitHub Actions workflows won't run without your approval"; rulesets and org policies apply. From 2025-06-04 each agent model request consumes one premium request. The article does not mention CODEOWNERS. — [GitHub Blog, 2025-05-19](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/)
- **2025-10-28 — Agent HQ (announced; rolling out):** "mission control" command centre across GitHub, VS Code, mobile and CLI to assign work to multiple agents in parallel and monitor progress; coding agents from Anthropic, OpenAI, Google, Cognition, xAI available "as part of your paid GitHub Copilot subscription" (no extra subscription); Codex already in VS Code Insiders for Pro+; custom agents via source-controlled **AGENTS.md** files; enterprise control plane: security policies, audit logging, access management, agent allowlists, model access, usage metrics; GitHub Code Quality (public preview); coding agent gains an integrated code review step. Quote, Mike Krieger (Anthropic CPO): Claude "can pick up issues, create branches, commit code, and respond to PRs". — [GitHub Blog, Agent HQ, 2025-10-28](https://github.blog/news-insights/company-news/welcome-home-agents/); [Visual Studio Magazine, 2025-10-28](https://visualstudiomagazine.com/articles/2025/10/28/github-introduces-agent-hq-to-orchestrate-any-agent-any-way-you-work.aspx)
- **2026-03 — agentic code review (secondary):** Copilot code review gathers full project context and can hand suggestions to the coding agent to generate fix PRs. — [secondary: nxcode.io guide](https://www.nxcode.io/resources/news/github-copilot-complete-guide-2026-features-pricing-agents)
- **2026-04-28/29 — custom agents:** defined as Markdown files describing behaviour, tools, standards and outputs; user-level agents in `~/.github/agents/`; org/enterprise owners can publish custom agents; "cloud agent" is now the name for the background coding agent; a Debugger agent validates fixes against runtime. — [GitHub changelog, 2026-04-29](https://github.blog/changelog/2026-04-29-github-copilot-in-visual-studio-april-update/); [Microsoft DevBlogs, 2026-04-28](https://devblogs.microsoft.com/visualstudio/visual-studio-april-update-cloud-agent-integration/)
- **Spec Kit (open source; shipped):** "gives your coding agent structured processes that keep intent and evidence ahead of implementation"; workflow Specify → Plan → Tasks → Implement → Converge; each phase produces Markdown documents in the repo; integrates with **38 coding agents** ("switch freely between agents with a single command. No lock-in"); 157 community extensions, 33 presets; additional processes include bug fixing and "idea assessment (evidence-backed decision making)"; includes checklists and quality validation. **The docs do not mention spec owners, formal approval workflows, or decision records.** — [GitHub Spec Kit docs](https://github.github.com/spec-kit/); 80,000+ stars and "24+ agents" per the earlier Microsoft write-up — [Microsoft for Developers, Spec Kit](https://developer.microsoft.com/blog/spec-driven-development-spec-kit/)
- Practitioner question "how do you progress beyond Specify with the cloud agent?" is an open discussion thread, i.e., the spec→agent handoff is not productised end-to-end. — [github/spec-kit discussion #2114](https://github.com/github/spec-kit/discussions/2114)
- **CODEOWNERS:** practitioner guidance recommends "use CODEOWNERS to ensure human sign-off on security-critical paths" for agent PRs; no GitHub announcement of CODEOWNERS changes for agents was found. — [secondary: nxcode.io guide](https://www.nxcode.io/resources/news/github-copilot-complete-guide-2026-features-pricing-agents)
- **GitHub Projects:** no agent-specific feature in Projects was found in any source; the "assign issue to Copilot" flow operates on Issues, not Projects. A community discussion asks how to create an issue and assign Copilot from a workflow, indicating it is API/automation-driven rather than a Projects feature. — [GitHub community discussion #186820](https://github.com/orgs/community/discussions/186820)

### Inferences
- GitHub's governance model is *path-derived* (CODEOWNERS, rulesets) and *repo-scoped*. It derives reviewers from files touched, which is the closest existing analogue to pjman's "approvers derived from the design record's deltas" — but at the level of code paths, not product features, disciplines/authorities, or design deltas (visual, data, second subtree).
- Spec Kit demonstrates demand for open, markdown-in-git, agent-agnostic process artifacts (80k+ stars) — validating pjman's Phase 1 shape — while leaving ownership/approval/decision/maturity entirely unaddressed.
- "Human must approve Actions" and "requester cannot approve their own agent PR" are the clearest shipped statements by any vendor that authorizing intent and accepting results are separate human moments; both are implemented as repository policy, not as a record.

### Gaps
- No primary GitHub source on CODEOWNERS evolution 2025–2026 was found (absence appears real, but was not confirmed against docs.github.com).
- GA date of Copilot coding agent beyond Enterprise/Pro+ (e.g., Pro/Business tiers) not confirmed in fetched sources.
- Spec Kit's licence and first release date were not captured from the fetched page.

## Key question 4 — Notion, Productboard, Aha!, Asana, monday.com, ClickUp, Shortcut and others: agent features for intake, triage, requests, roadmaps

### Takeaway
Every PM/work tool now ships "agents as teammates" with memory and triggers (Notion 3.0 2025-09-18; monday.com agent accounts 2026-03-11; Asana AI Teammates GA ~March 2026; ClickUp Super Agents 2026; Shortcut's Korey; Productboard Spark 2026-06-22). The intake/triage/spec layer is being automated (Productboard's codebase-grounded specs pushed to Claude Code/Codex/Cursor over MCP; Korey turning notes into stories with acceptance criteria). **None** ships derived approvers, typed decision records, maturity-with-evidence, or drift detection; Productboard's "evidence-ranked opportunities" and "cited findings" are the nearest thing to evidence-as-data.

### Cited Findings
- **Notion 3.0 — 2025-09-18 (shipped):** Notion AI rebuilt as Agents; "over 20 minutes of multi-step actions"; memory via pages/databases; executes multi-page workflows, updates hundreds of pages, accesses Slack/Drive/GitHub; **Custom Agents** run on schedules or triggers (customer feedback management, project updates, IT requests), respecting user permissions; Claude Sonnet 4 and GPT-5 included with no per-model fee; database row permissions on Business/Enterprise. ## Key question 6 — Analyst and practitioner commentary: trackers as the "coordination layer"; bottleneck shifting from execution to review/decisions

### Takeaway
The quantitative record (DORA 2025; Faros's 22,000-developer dataset; Stack Overflow 2026) supports the thesis that execution is no longer the constraint: AI raises individual output (21% more tasks, 98% more PRs merged) while organisational delivery stays flat, review time balloons (+91% code review time; median PR review time up 441% in 2026 data), and only 6.6% of developers would trust AI with an important decision. Practitioner essays frame "review as the new bottleneck" and "trackers as input layers for coding agents". No Pragmatic Engineer, a16z or Gartner primary piece specifically on trackers-as-coordination-layer was found.

### Cited Findings
- **DORA 2025 (September 2025):** 95% of developers use AI tools; >80% report productivity gains; "AI boosts individual output—21% more tasks completed, 98% more pull requests merged—but organizational delivery metrics stay flat"; AI is an "amplifier" of existing conditions; seven AI capabilities (clear AI stance, healthy data ecosystems, AI-accessible internal data, strong version control, small batches, user-centric focus, quality internal platforms); seven team archetypes replace performance tiers. Faros: code review time +91%; median PR review time +441% in 2026 data; PR size +154%. — [Faros AI, DORA 2025 takeaways](https://www.faros.ai/blog/key-takeaways-from-the-dora-report-2025); [DX podcast on DORA 2025](https://getdx.com/podcast/doras-2025-research-on-the-impact-of-ai/)
- Faros followed 22,000 developers: median review takes five times as long as before on PRs half again as large; developers say AI-written code takes more effort to review than a colleague's. — [secondary: Philipp Dubach summary](https://philippdubach.com/posts/93-of-developers-use-ai-coding-tools.-productivity-hasnt-moved./)
- **Stack Overflow Developer Survey 2026 (published 2026-10-06):** 73% of AI-tool users use them daily; 31% of daily users spend 4+ hours/day; 66% use coding agents, 63% chatbots; 66% name Claude Code as agent of choice, 59% GitHub Copilot; 20% use AI to deploy/operate production; 93% require source attribution to trust AI context; 38% of organisations set AI usage limits. — [Stack Overflow blog, 2026-10-06](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)

### Inferences
- The data supports pjman's bet 2 ("execution is cheap and competent, not infallible"): adoption is near-universal, trust is conditional on verification and attribution (93% require source attribution), and decision-trust is near zero (6.6%). That is a market statement that humans will keep authorising and accepting, which is the role pjman designs around.
- The bottleneck literature is almost entirely about *code review*; the step before it — deciding what to build, by whom, with what authority — is discussed only in org-design essays, not measured. pjman's "alignment" framing is upstream of where the industry currently measures pain, which is both an opportunity and an evidence gap for the pitch.
- "Trackers as coordination layer" is the vendors' own framing (Linear "context infrastructure", Atlassian "control plane", GitHub "mission control"); independent analysts mostly describe governance/control planes for agents (Thoughtworks Agent/works, Futurum), not decision/ownership models.
