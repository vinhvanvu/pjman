# Build the record now, defer the business


## Nobody ships the join, but every piece of it exists somewhere

The memory category is large, funded and almost entirely about facts. Mem0 raised **$24M** and sits at **66.9k GitHub stars** storing LLM-extracted "conversation context and user preferences" ([PR Newswire](https://www.prnewswire.com/news-releases/mem0-raises-24m-series-a-to-build-memory-layer-for-ai-agents-302597157.html); [GitHub](https://github.com/mem0ai/mem0)); Cognee raised **$7.5M** for an entity/relationship graph across relational, vector and graph stores at **31.9k stars** ([cognee.ai](https://www.cognee.ai/blog/cognee-news/cognee-raises-seven-million-five-hundred-thousand-dollars-seed); [GitHub](https://github.com/topoteretes/cognee)); claude-mem, at **99k stars**, captures observations from tool use into SQLite and Chroma and is the one memory tool that tags a `decision` type — but derived by a model, with no rationale schema, no ticket, no owner ([GitHub](https://github.com/thedotmack/claude-mem)). Unblocked ($20M Series A) explicitly mines "why decisions were made" from Slack and PRs, hosted and closed ([getunblocked.com](https://getunblocked.com/blog/unblocked-context-engine-for-agents/)). pjman's "not a memory tool" line is factually accurate against all of them: none stores a unit of work, an authored decision, or a binding to an external identity. The tools whose *shape* resembles pjman are the git-native structure-of-work tools: Beads (**27.8k stars**, MIT) is a dependency-graph issue tracker with typed links (`blocks`, `parent-child`, `supersedes`, `replies-to`) stored in a Dolt database, with no decision type, no Linear/Jira binding and no hosted offering ([GitHub](https://github.com/steveyegge/beads)); Entire, Thomas Dohmke's **$60M seed** bet that "why" belongs in version control, stores agent transcripts as git refs and by its own README "primarily documents the interaction history rather than narrative decision-making" ([entire.io](https://entire.io/news/former-github-ceo-thomas-dohmke-raises-60-million-seed-round/); [GitHub](https://github.com/entireio/cli)); Graphify (YC S26) commits a typed, confidence-tagged code graph to the repo across 20+ harnesses with no authored layer at all ([GitHub](https://github.com/Yyunozor/graphify)).

The spec-driven category is procedural where pjman is declarative. Spec Kit (**140,599 stars**, roughly +33k in five months, 84k PyPI downloads a month) runs constitution → specify → plan → tasks → implement as markdown in numbered feature folders, with no decision record beyond an assessment extension's go/kill verdict, a one-way tasks→GitHub-issues export, no edges and no JSON surface ([GitHub](https://github.com/github/spec-kit); [pypistats](https://pypistats.org/api/packages/specify-cli/recent)). OpenSpec is the one with real pull — **2.69 million npm downloads a month**, about 30× any other open tool — and the one whose design is nearest pjman's second pole: a CLI with `--json` everywhere, data-defined workflow schemas, and "Stores" that make location pluggable ([GitHub](https://github.com/Fission-AI/OpenSpec); [npm](https://api.npmjs.org/downloads/point/last-month/@fission-ai/openspec); [Stores guide](https://github.com/Fission-AI/OpenSpec/blob/main/docs/stores-beta/user-guide.md)). It still has no edges between changes, no typed decision and no documented ticket binding. Taskmaster has a ticket field, but as an untyped `metadata` blob ([docs](https://tryhamster.com/docs/taskmaster/capabilities/task-structure)), and its development stopped after April 2026 ([GitHub](https://github.com/eyaltoledano/claude-task-master)). GSD Core comes closest on decisions — per-phase `CONTEXT.md`, a `DISCUSSION-LOG.md`, a rolling `DECISIONS-INDEX.md` — but phase-scoped prose with no who/when fields ([planning artifacts](https://github.com/open-gsd/gsd-core/blob/main/docs/reference/planning-artifacts.md)). The only tool found that models decisions as typed objects with lineage is Memex, which does so in Postgres behind a server, Claude-only, at **29 stars** ([spec-compare review](https://github.com/cameronsjo/spec-compare/blob/main/docs/memex-review.md)). Tessl, the best-funded independent at **$125M**, pivoted away from spec-driven development entirely to a skills registry in January 2026 ([codemyspec](https://codemyspec.com/blog/tessl-review); [HN](https://news.ycombinator.com/item?id=46826730)).

| Nearest neighbour | Decision with rationale | Ticket binding | Typed edges | Authored vs derived | CLI / index | Where it lives |
|---|---|---|---|---|---|---|
| Beads | No | No | Yes (issues) | No | Yes | Dolt DB in `.beads/` |
| OpenSpec | Prose in `design.md` | Not documented | No | Specs vs changes only | Yes, `--json` | Markdown in repo |
| Taskmaster | No | Untyped `metadata` | Task DAG | No | Yes, MCP | `tasks.json` |
| GSD Core | Prose, per phase | No | Req-ID ↔ phase | Partial (`STATE.md`) | Internal | `.planning/` |
| Memex | **Yes, typed** | Unknown | Graph | No | Server | Postgres, hosted |
| claude-mem | Derived tag only | No | No | Derived only | Yes | SQLite + Chroma |
| Entire | AI summary of intent | No | No | Derived only | Yes | git refs |
| pjman Phase 1 | Authored, who/why/when | `binds`, validated | `parent`, `affects`, `decided`… | In schema | Library + index | Markdown in git |

The trackers and PM tools validate the problem loudly and ship none of the model. Linear made agents first-class workspace members in May 2025 ([changelog](https://linear.app/changelog/2025-05-20-linear-for-agents)), shipped its own agent, its own code review surface and its own coding sessions via Claude Code and Codex by June 2026 ([changelog](https://linear.app/changelog/2026-06-11-coding-sessions)), and its CEO declared "issue tracking is dead" and that "decisions, and code all need to be captured in a system that humans and agents can work from together" ([The Register](https://www.theregister.com/2026/03/26/linear_agent/); [Tessl](https://tessl.io/blog/issue-tracking-is-dead-linear-ceo-explains-why-the-company-is-betting-on-agents)) — yet the full 2026 changelog contains **no decision object, no ownership beyond assignee and lead, no approvals on issues** ([changelog index](https://linear.app/changelog)). Atlassian opened its Teamwork Graph (150B+ connections, a CLI, an MCP server) and markets it as capturing "why a decision was made, who owns it now" ([SiliconANGLE](https://siliconangle.com/2026/05/06/atlassian-opens-teamwork-graph-pushes-rovo-agentic-execution-team-26/); [Atlassian blog](https://www.atlassian.com/blog/company-news/teamwork-graph-team-26)), but its developer glossary defines no Decision, Owner or Approval type — only work item, document, project and user, with canonical/activity/inferred relationship classes ([glossary](https://developer.atlassian.com/platform/teamwork-graph/glossary/)). GitHub's CODEOWNERS is the single shipped instance anywhere of approvers derived from what a change touches, at the level of file paths, unchanged for agents; its coding agent's "requester cannot approve their own agent PRs" is the clearest vendor statement that authorizing intent and accepting results are separate moments, implemented as repository policy rather than as a record ([GitHub blog](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/)). Productboard Spark pushes codebase-grounded specs to Claude Code, Codex and Cursor over MCP and stops at spec generation ([Productboard](https://www.productboard.com/blog/introducing-spark-agentic-product-system/)).

The catalog and knowledge-graph layer tells the same story from the ownership side, and adds the historical warning. Backstage has **3.4k+ adopters and ~31k stars** ([Backstage Wrapped 2025](https://backstage.io/blog/2025/12/30/backstage-wrapped-2025)); its best-documented failure is a hand-authored `catalog-info.yaml` that is costly to populate, goes stale and erodes trust — a critique made by competitors ([Port](https://port.io/blog/what-are-the-technical-disadvantages-of-backstage)) and conceded by its own vendors ([Roadie changelog](https://roadie.io/changelog/3)). The commercial response is auto-discovery and inferred ownership from repo activity, now a commodity at Cortex, OpsLevel and the late Compass ([Cortex](https://www.cortex.io/post/atlassian-compass-end-of-life-what-to-do-next); [OpsLevel](https://www.opslevel.com/resources/opslevel-releases-recommended-service-owners-to-optimize-service-management-efficiency)); Port raised **$100M at $800M** to become an agent "Context Lake" ([TechCrunch](https://techcrunch.com/2025/12/11/port-raises-100m-at-800m-valuation-to-take-on-spotifys-backstage)); Atlassian closed Compass to new customers on 2026-05-13 and folded it into DX, with scorecards that do not even migrate ([Atlassian](https://support.atlassian.com/compass/docs/migrate-from-compass-to-dx/)). Blitzy raised **$200M at $1.4B** for a knowledge graph "of the enterprise codebase" — observed state only ([SiliconANGLE](https://siliconangle.com/2026/05/05/blitzy-raises-200m-1-4b-valuation-deploy-thousands-coding-agents-parallel/)). Every IDP's "maturity" is a scorecard against policy; none models maturity as a claim with graded evidence, none holds a product-feature tree, none surfaces drift between a declared claim and the observed mapping. Three consequences for pjman follow. First, "harness-agnostic" is table stakes — claude-mem supports ten harnesses, OpenSpec ~35, Graphify 20+ — and "graph" is not a unique word (Asana's Work Graph, Atlassian's Teamwork Graph); the differentiation has to be what is stored. Second, derived ownership at the service level is already solved; pjman's claim has to be ownership attached to *features*, which exist in no repo. Third, the clearest unoccupied cell is the authored decision as a typed, validated record that agents and tools rely on — recognised as valuable by Anthropic's own `project` memory type ("ongoing work, deadlines, and decisions"), by Linear's CEO, by practitioners ([code.claude.com](https://code.claude.com/docs/en/memory); [Davidson](https://duncandavidson.com/agents-love-decisions)) — and implemented nowhere.

## The pain is measured at the review gate, one step below pjman's pitch

The best-evidenced part of the thesis is the authorization bottleneck. GitHub merged **43.2 million PRs a month, up 23 % year on year**, with Copilot's agent alone opening over a million between May and September 2025 ([Octoverse 2025](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)). Faros's two-year telemetry over 22,000 developers reports PRs merged **+98 %**, median time to first review **+156.6 %**, median time in review **+441.5 %**, PRs merged without any review **+31.3 %**, bugs per developer **+54 %** and incidents-to-PR **+242.7 %** ([Faros](https://faros.ai/blog/ai-acceleration-whiplash-takeaways)). LinearB's 8.1M-PR benchmark finds AI pull requests merge within 30 days **32.7 % of the time against 84.4 %** for unassisted work, with agentic PRs waiting 17.6 hours at P75 versus 3.4 ([LinearB](https://linearb.io/library/ai-in-software-development)). DORA 2025 — survey, not vendor telemetry — finds 90 % AI adoption, a continued negative relationship with delivery stability, and the sentence closest to the thesis a neutral body has written: gains become "localized pockets of productivity that are often lost in downstream chaos," with returns depending on "the clarity of workflows, and the alignment of teams" ([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report); [InfoQ on DORA ROI](https://infoq.com/news/2026/05/dora-roi-ai-assisted-dev-report)). "PRs merged without review up 31 %" alongside "38 % of reviewers deprioritise AI PRs" is THESIS.md's "accountability without evidence is a rubber stamp" in measured form. On the demand side for human authority, the Stack Overflow 2026 survey (30,000+ respondents) has 66 % using coding agents, **93 % requiring source attribution** to trust output, and **only 6.6 %** willing to trust AI with important work decisions ([Stack Overflow](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/); [IT Brief](https://itbrief.co.uk/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)) — a market statement that humans will keep authorising and accepting, which is the role pjman designs around.

The friction is organisational, as the thesis says, but the surveys name it as information-finding and cross-team collaboration, not "alignment." Atlassian's 2025 developer-experience survey has **50 % losing 10+ hours a week to non-coding tasks**, led by finding information, context switching and "collaboration with other teams," which moved up the ranking; coding was not listed as a time-waster in either year, though developers spend only 16 % of their time on it ([Atlassian](https://www.atlassian.com/blog/developer/developer-experience-report-2025)). Anthropic's own internal study records the mechanism THESIS.md names — the engineer ceasing to be the record — in the words of its staff: "80–90 % of [questions] go to Claude," "more junior people don't come to me with questions as often" ([Anthropic](https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic)). And the memory-tool literature has converged on precisely the properties pjman specifies: Mem0's own state-of-the-field report lists staleness ("confidently wrong" outdated facts) as an open problem ([Mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026)); an August 2026 arXiv paper instrumenting 78,933 hook invocations names staleness, contradiction, pollution and silent failure as the failure classes ([arXiv](https://arxiv.org/abs/2609.05510)); Davidson reports an agent preserving an obsolete abstraction because a stale ADR still described it as mandatory, and concludes memory systems "preserve context without establishing whether it is accurate, current, or accepted by the human team" ([Davidson](https://duncandavidson.com/agents-love-decisions)). The labs' own responses — Cursor removing Memories in 2.1 ([Cursor forum](https://forum.cursor.com/t/custom-modes-and-memories-gone-in-2-1/143744)), Copilot expiring memories after 28 days and validating them against the codebase ([GitHub changelog](https://github.blog/changelog/2026-03-04-copilot-memory-now-on-by-default-for-pro-and-pro-users-in-public-preview/)), Claude Code's silent plan-pickup failure filed as issue #54720 ([claudeissues](https://claudeissues.com/issue/54720-plan-pickup-is-broken-you-told-users-a-new-session-resumes-it-doesnt)) — are evidence that unstructured, unowned, unversioned context is a liability, which is the case for status, supersession, provenance and "drift surfaced, never hidden."

### The counter-evidence, given full weight

Four lines of evidence cut against the thesis and should not be softened. First, **"execution is easy" is not established.** METR's RCT found experienced open-source developers **19 % slower** with AI while believing they were 20 % faster; its February 2026 follow-up with 57 developers and 800+ tasks could not produce a reliable estimate and calls its own data "only very weak evidence" of improvement ([METR](https://metr.org/blog/2026-02-24-uplift-update/)). Stanford's commit-level analysis across 100,000+ engineers finds 15–20 % average gains, concentrated at 30–40 % on greenfield work and **0–10 % on complex brownfield work** — the work most organisations do ([AI Engineer talk](https://www.ai.engineer/talks/tbDDYKRFjhk-ai-developer-productivity)); Bain reports 10–15 % gains that "don't translate into positive returns" ([Bain](https://www.bain.com/insights/from-pilots-to-payoff-generative-ai-in-software-development-technology-report-2025/)). If execution is not yet cheap, the bottleneck has not yet moved as far as the pitch assumes. Second, **the labs now ship a record**, undermining "there is no record" for facts: Claude Code auto-memory on by default since v2.1.59 (February 2026), Copilot Memory, Codex project memory, Gemini `save_memory`, Cursor Projects "maintaining context over months of work" in Cursor's cloud ([code.claude.com](https://code.claude.com/docs/en/memory); [Cursor changelog](https://cursor.com/changelog/projects)). Third, **developers reject process overhead.** 69.2 % of developers in the 2025 Stack Overflow survey do not plan to use AI for project planning ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai)); AWS had to add bugfix and design-first workflows to Kiro because "most developers don't work the way Kiro forces them to" ([CIO](https://www.cio.com/article/4135314/aws-adds-design-first-and-bugfix-workflows-to-kiro-2.html)); Thoughtworks put spec-driven development at *Assess* and did not carry it into the 2026 Radar ([Thoughtworks](https://www.thoughtworks.com/radar/techniques/spec-driven-development)); the OpenSpec thread reports engineers who "abandoned OpenSpec entirely, reverting to single markdown files or architecture decision records," and a user of its sync who stopped because "it just keeps drifting and drifting until you have duplication and contradictions across specs" ([HN](https://news.ycombinator.com/item?id=49734264); [HN](https://news.ycombinator.com/item?id=47994433)). Fourth, **structure has a measured cost and the cheap alternative works.** The ETH Zurich AGENTS.md benchmark found LLM-generated context files *reduced* agent success by ~3 % and raised cost by over 20 %, while human-written ones raised success by only ~4 % at up to +19 % cost ([InfoQ](https://infoq.com/news/2026/03/agents-context-file-value-review/)) — a direct warning that pjman's derived session records, if fed back to agents, are not automatically safe, and that the authored half earns its keep only if it is small and curated. The traceability literature's industrial record is that hand-maintained intent-to-code links go stale and are abandoned, and that a large telecom shipped complex software successfully *without* them, "contradicting academic assumptions that such links are essential" ([Fucci et al.](https://ar5iv.labs.arxiv.org/html/2206.04462)). ADRs are Thoughtworks *Adopt* since 2017 yet used by **47 %** of architecture practitioners ([IcePanel](https://icepanel.io/blog/2024-11-26-state-of-software-architecture-2024)), half of ADR-using repos hold one to five records ([Buchgeher et al.](https://research.jku.at/en/publications/using-architecture-decision-records-in-open-source-projects-an-ms/)), and **63 % of 5,800 ADRs were opened already "accepted"** — written as documentation after the fact, not as the decision ([ICSA 2026](https://conf.researchr.org/details/icsa-2026/icsa-2026-papers/34/Architecture-Decision-Records-Adoption-Impact-and-Developer-Engagement-in-Open-Sou)). That last figure is the sharpest risk to pjman's "the only authored thing is the decision": a decision record has value only if it is the artefact *through which* the decision is made.

The largest evidentiary hole is specific: **no study quantifies the cost of context loss between agent sessions, decision latency in product organisations after agents, or whether structured decision records improve agent outcomes.** The thesis's "alignment" framing is upstream of where the industry measures pain (code review), which is both the opportunity and a gap the pitch cannot currently fill with numbers. The solo-founder evidence (companies at $400M in sales with no employees, promotional and unaudited) is weak as data but consistent with THESIS.md's own concession that a solo developer "has no alignment pain" — which means the paid tier's buyer is an organisation and the free tier's user is not that buyer.

## Phase 1 matches the absorption survivors; Phases 2–3 sit where the labs are heading

The 2025–26 absorption record is unambiguous about *what* gets absorbed. Between June 2025 and August 2026 the harness vendors shipped natively nearly everything third parties had built around them — hooks, subagents, plan mode, plugins, tasks with dependencies — and per-user or per-repo memory converged across all four within ten months: Cursor June 2025 ([Cursor 1.0](https://cursor.com/changelog/1-0)), Copilot January 2026 ([GitHub changelog](https://github.blog/changelog/2026-01-15-agentic-memory-for-github-copilot-is-in-public-preview/)), Claude Code February 2026 ([havoptic](https://www.havoptic.com/r/claude-code-2.1.59)), Codex April 2026 ([Supermemory](https://supermemory.ai/changelog/memory-for-openai-codex)). What survived were tools that are cross-harness and own a data layer the harness does not export: claude-mem reached 72k stars *after* native auto-memory shipped ([Augment Code](https://www.augmentcode.com/learn/claude-mem-65k-stars)); Supermemory made its per-harness plugins free and sells the cross-harness workspace. The labs' memory is harness-locked by design — Codex's is "project-scoped, cloud-only, and locked inside OpenAI," Copilot's lives in GitHub, Claude Code's is machine-local — because lock-in is their business model. This maps onto THESIS.md's durability test with uncomfortable precision: the procedural layer it keeps thin (step sequencing, wizards, decomposition) is exactly what got absorbed, and the data layer it builds (the graph, who decided what, gates) is exactly what did not. On paper Phase 1 is a survivor.

Phase 2 is not. The team-scoped shared graph is where the biggest players are visibly moving: Anthropic's reported 2026 roadmap includes agents persisting insights "across an entire team" ([attendee report](https://www.mejba.me/blog/code-with-claude-2026-agent-future-preview), secondary and unverified); Copilot's repository-scoped memory is already shared across coding agent, review and CLI and "validated against the current codebase" — a drift check — and GitHub owns the repo, PR and merge evidence that is pjman's observed state plus Spec Kit's records-in-repo shape ([GitHub changelog](https://github.blog/changelog/2026-03-04-copilot-memory-now-on-by-default-for-pro-and-pro-users-in-public-preview/)); Linear's trajectory is *downward* into execution (own coding agent, sandbox pricing, model routing) rather than upward into decisions, but either Linear or Atlassian could add a Decision object and an owner field in one release, and both have said in public that they should. The gap pjman occupies is open only while organisations are multi-harness; if one harness wins an organisation, it closes. The founder's own daily tool is Linear-bound, which is the right source to bind to and also the vendor whose CEO says "context becomes the product" ([BigGo summary of Lenny's Podcast](https://finance.biggo.com/news/936aa818c5c732f4)).


The economics do not close on the solo tier, and the licence protects little either way. Developer-tool freemium converts at roughly 1–3 % and open-source-to-paid at 0.5–3 % ([Monetizely](https://www.getmonetizely.com/articles/whats-the-optimal-conversion-rate-from-free-to-paid-in-open-source-saas)); at $10/month, 10,000 active free users yields about **$12k–$36k a year**. Every bootstrapped comparable took four to ten *full-time* years to a few million ARR: Plausible reached $1M ARR four years after launch ([Indie Hackers](https://www.indiehackers.com/post/we-just-reached-the-1m-arr-milestone-32722fc93e)), Sidekiq took "ten years to become an overnight success" ([Indie Hackers](https://indiehackers.com/podcast/016-mike-perham-of-sidekiq)), and both sell something the framework user cannot self-provide cheaply rather than hosting of a free framework. No comparable was found where a founder with a day job reached meaningful revenue. Tidelift's maintainer survey has **54 % citing competing life demands and 44 % burnout** as reasons to quit, with 60 % unpaid ([FOSS United summary](https://forum.fossunited.org/t/opinionated-summary-of-tidelift-state-of-open-source-maintainer-report/4066)) — the exact profile of a staff engineer maintaining adapters for four churning harnesses in the evenings. On licence, the permissive-then-tighten pattern (Plausible MIT→AGPL after hosted free-riders approached it, HashiCorp, Elastic, Redis, Sentry's FSL) happened post-traction in every case and required holding the copyright ([Plausible](https://ingest.plausible.io/blog/open-source-licenses); [WZ-IT chronicle](https://wz-it.com/en/blog/open-source-licence-change-chronicle/); [Sentry](https://blog.sentry.io/sentry-is-now-fair-source)); Cal.com, the closest shape to pjman's "free framework + hosted paid," went fully closed on its commercial edition in April 2026 citing AI making vulnerability discovery in public code easier ([Cal.com](https://cal.com/blog/calcom-v6-4)) — which cuts against "an agent clones it in a weekend" as a reason not to worry, though pjman's hosted server stays closed regardless. Apache-2.0's patent grant and contribution terms favour anything that may later have a company behind it ([Linuxiac](https://linuxiac.com/mit-and-apache-2-0-lead-open-source-licensing-in-2025/)); MIT is what the closest peers chose for the community artefact. The decision that matters is a DCO or CLA from day one so a later change stays possible. The right trust model to copy is Obsidian's — open *format*, closed app, revenue from sync ("runs on ours") — a bootstrapped survivor whose line matches pjman's exactly ([TfT Hacker](https://tfthacker.substack.com/p/getting-to-know-the-ceo-of-obsidian)).

## Verdict: a bounded go on the record, a no-go on the business premise


The no-go is on treating Phases 2–4 as premises. The business depends on per-signer pricing, which depends on Phase 3's derived approvers and bounded asks, which depends on "a team with real approvals" that the founder does not have and a buyer (a manager with authority) who is not the founder and is not tested by the second user. The solo tier cannot fund it, the shared graph is where GitHub and Anthropic are heading, and the one measured number the pitch rests on — decision latency, context-loss cost — does not exist. None of that argues against Phase 1; it argues against spending Phase 1 time designing for Phase 3, and against letting "the schema is independent of storage" pull the schema toward hosted-graph generality before a second person has written a decision into it.


| Weeks | Test | Pass signal | Kill signal |
|---|---|---|---|
| 1 | Schema spec from the session board's `DESIGN.md`, capped at one week | Change, session, source, decision records and the edge set written down; status vocabulary as data | Spec grows past a week or acquires Phase 3 fields (authorities, rubrics, asks) |
| 2–4 | Library + CLI (read, write, validate, index, JSON); port the skill, mod and sidebar | Founder's daily work runs on the framework; the three hard-coded values are configuration | Port stalls; the old tool is still the one in use |
| 3–6 | The join test on real work: `binds` a Linear ticket, author decisions, let sessions append observed edges | An agent reads a prior decision at decision time and acts on it; drift surfaced at least once and it mattered | Decisions are written after the fact (the 63 % pattern); nothing reads them; the folder would have done |
| 5–8 | Second user, different stack, README only | Installs without code edits; a record survives two weeks of their work | Requires a `.gd`-style edit to the framework to fit their tools |

## Conclusion

The research reframes the question from "is the thesis right" to "is the record worth keeping." The alignment thesis is directionally supported but unmeasured; the record — a change bound to a ticket, a decision with who/why/when, authored and derived kept apart, drift surfaced — is where every neighbouring category's documented failure converges and where no one has built. That makes pjman's Phase 1 less a bet on a market than a bet on a *format*: the thing the memory vendors, spec frameworks and trackers would each need if their own rhetoric about decisions were ever to become schema. The Obsidian lesson is that an open format with a closed service can be a bootstrapped business, but only once the format is in other people's hands; the Cal.com and Tessl lessons are that open code is neither a moat nor, lately, safe; the absorption record's lesson is that the data layer survives and the workflow does not.

Two implications follow for how to spend the evenings. The pitch should be re-anchored at the gate the industry already measures — authorization and acceptance, where review time is up fourfold and a third of PRs merge unreviewed — rather than at "alignment," which nobody has quantified; pjman's separation of authorizing intent from accepting the result is the feature that maps onto measured pain. And the first eight weeks should be run as an experiment with a kill criterion rather than as the start of a roadmap: the only question that matters now is whether a typed decision record, in git, read by an agent, beats a folder of markdown on the founder's own work. If it does, the option on Phases 2–4 is worth holding while watching whether Linear or GitHub ships a Decision type. If it does not, the research says the market will not either.
