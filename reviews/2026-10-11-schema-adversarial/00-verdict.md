# Adversarial round 1 — schema v2 and the Phase 1 plan — verdict

*2026-10-11. Six independent reviewers, each briefed to falsify one load-bearing claim, read-only. Their reports are the numbered files beside this one. This is the judiciary read: what converged, what it means, and the recommendation.*

## Verdict

**Schema v2 does not hold as written, and the Phase 1 plan tests the wrong thing first.** The reviewers did not disagree with the thesis; they found that the schema front-loads Phase 2/3 machinery (UUID identity, the envelope, storage independence, layers 3–4, actor records, an index) while pruning the fields the daily workflow actually reads (`next`, `goal`, PRs, plan), that several of its rules are unimplementable or self-contradictory, and that the hand-built store — the "walk-through" — exercised none of the claims the schema exists for (zero `binds`, seven of seven decisions opened `decided`, observed edges that duplicate authored links, 18 % of records invalid YAML). The null-hypothesis reviewer put it at ~80 % that a disciplined folder convention plus a 20-line validator is enough for Phase 1, and the plan reviewer found the fastest path to the research report's test is 5–8 evenings, not the 5–7 weeks the current order implies.

## What converged (named by ≥2 reviewers)

1. **UUIDs inside files are wrong for a file format.** 3.1× the tokens of keys, unreadable in a PR diff, error-prone for an LLM to author, and the schema already grants actors a key-form reference for exactly these reasons. References in files should be keys (`linear:ABC-1234`, `change:schema`, `person:vinh`); ids stay in the index. (01, 02, 03, 04)
2. **`updated` and the derived-field rule must go.** `updated` turns every concurrent edit into a git conflict; "a hand edit to a derived field is drift" needs a baseline the schema forbids (the index is disposable) or git (contradicting storage independence). `created` and the id encode two different clocks in the store already. (01, 02, 03)
3. **The layer-dependency rule is false three times in the schema's own text** (envelope `session` 0→1, actor `links` 0→1, observed edges with a change as `from` 1→2), and `touches` is named and drawn but has no table row. (01)
4. **YAML as written is fragile:** 4 of 22 hand-written records are invalid (titles containing `: `), and one is referenced by three others, so a strict reference check fails 7 of 22. Phase 0's `key: <JSON>` lines never had this problem. (03, 01)
5. **The walk-through was not a test.** Every decision was written after the fact (the 63 % pattern the research named as the sharpest risk); no change binds a source; the session record is hand-written and self-exempted; no commit carries the provenance trailer the schema requires. (01, 04, 05)
6. **Phase-3 leakage:** `owner` with no meaning, all of layer 3 with zero features, actor `aliases`, session `parent`, the audit-log sentence, two storage locations, "schema independent of storage". Meanwhile `on_behalf_of` was pruned, which breaks the second-user case (two humans, one harness, records whose human cannot be recovered). (05, 06, 04)
7. **Drift as defined is unreachable in Phase 1** (it needs a Linear sync adapter that isn't scheduled), and it does not address the one case cited against the folder (a stale decision versus the code). (04, 05)

## What did not converge, or is Phase 3's

Status vocabulary is Linear's renamed and lacks an approval state (06) — true, and layer 4's. Committee deciders, store-qualified handles, a claim/lease primitive (06) — Phase 2+. Session filename collisions within a 65-second window (01, 02) — real, trivial, fix when sessions are generated by code.

## Recommendation

**Shelve schema v2 as the Phase 2 target. Build Phase 1 as the folder plus a validator, and run the test.** Concretely:

- **Format:** slug-keyed change folders; records as Markdown with a small frontmatter whose references are keys, not ids; decisions with `status` (`proposed | decided | superseded | reverted`), `decided_by`, `decided_on`, `supersedes`; `next` and PR links back in the contract; no envelope beyond what git gives (`writer` and `session` only where an adapter writes them). No layer 3, no actor records, no index.
- **Tool:** one file, four verbs — `new`, `validate` (the invariants that matter: references resolve, a decision marked decided has its two fields, a superseded decision has a superseder, status in vocabulary), `ls --json`, `context <change>` (the orientation surface, with a token ceiling). Five to eight evenings.
- **Adapters:** a hook that injects `context` at session start and a skill rule that opens a decision `proposed` before acting; a one-evening bridge that emits Phase 0's `summary.md` as a view so the sidebar keeps working. No re-derived pane or sidebar until the test passes.
- **Rule from here:** schema commits may not outnumber code commits.

What survives from v2 into the Phase 2 target: the layer idea, authored versus derived as a concept, keys-in-files with ids-in-index, actors as records, sessions with `parent` and a human on behalf of whom, observed edges with provenance, and the storage-backend split stated as a backend section rather than a layer-0 claim.
